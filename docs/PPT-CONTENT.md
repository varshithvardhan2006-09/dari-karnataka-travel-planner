### Slide 4: How Dari is Fundamentally Different

**Header:** The Dari Advantage: 5 Architectural Pillars  
**Key Differentiators:**  
1. **Real Places Only (Zero Hallucination Guarantee):**  
   The AI model is never allowed to generate free-text place names, coordinates, or prices. It selects strictly from curated place IDs in `data/places.json`. Unknown IDs are automatically rejected by the server.  
2. **First-Class Kannada (ಕನ್ನಡ):**  
   One toggle switches interface, place names, descriptions, and tips to certified Kannada. All Kannada text is pre-curated — never generated by LLMs at runtime.  
3. **Contextual Phrases with Audio at Every Stop:**  
   Every stop features 2–3 relevant phrases (e.g. ticket booking, asking for water, ordering Mysore Masala Dosa, darshan timings) with Kannada script, English transliteration, English meaning, and native `kn-IN` voice audio.  
4. **Works 100% Offline from the AI:**  
   Built-in deterministic nearest-neighbour heuristic planner runs without API keys or during cloud outages.  
5. **Itemized Rupee Budget Invariant:**  
   Transparent cost breakdown where `Stay + Food + Transport + Entry === Total` mathematically.  

> **Speaker Notes (1:35 - 2:15):**  
> *"Dari stands on five pillars. First: zero hallucinations. By constraining the LLM to valid place IDs, it physically cannot invent a fake place. Second: genuine Kannada. We never trust an LLM to generate Kannada at runtime; all Kannada text is human-verified in UTF-8 datasets. Third: practical phrasecards with browser speech synthesis at every monument. Fourth: 100% offline fallback planner. And fifth: real rupee cost estimates for stay, food, transport, and entry."*

### Slide 5: Engineering Approach & Pipeline

**Header:** Engineering Pipeline: Constrained Retrieval & Fallback  
**Pipeline Flow:**  
- **Step 1: Validation & Rate Limiting:** Zod validates request constraints (1–7 days, max 4 interests); in-memory IP rate limiter prevents API abuse.  
- **Step 2: Candidate Retrieval & Scoring:** `getCandidates()` scores 36 curated places based on interest match (weight 40), best travel month (weight 25), budget tier (weight 20), and Haversine distance from the starting city.  
- **Step 3: Constrained AI Cascade:** Primary Groq API (Llama 3.3 70B, JSON mode) executes in < 1.5s; falls back to Google Gemini (2.5 Flash). Zod validates output; retries once with specific error feedback.  
- **Step 4: Deterministic Fallback:** `buildDeterministicPlan()` clusters places geographically and enforces pace limits (2–3 stops relaxed, 3–4 balanced, 4–6 packed).  
- **Step 5: Geometric & Financial Enrichment:** Computes road distance (Haversine × 1.3), realistic driving time (40 km/h + 10 min buffer), auto/cab/bus mode selection, and itemized rupee costing.  

> **Speaker Notes (2:15 - 2:55):**  
> *"Our pipeline follows a strict cascade: we filter the top candidate places from our database, send only their IDs and coordinates to Groq's Llama 3.3 70B model with a strict JSON schema. If Groq rate limits, we fall back to Google Gemini Flash. If Gemini is unavailable, our deterministic heuristic planner immediately takes over. The plan is then enriched with real road geometry, drive times, and human-verified Kannada phrases."*

### Slide 6: Architecture Diagram & Tech Stack

**Header:** System Architecture & Clean Tech Stack  
**Visual:** Embeds `00-architecture.png`  
**Stack Components:**  
- **Framework:** Next.js 16.4.2 (App Router) + TypeScript + React 19  
- **Styling & Tokens:** Tailwind CSS v4 with Karnataka flag palette (`#8E1F2F` crimson, `#F2B705` gold)  
- **Typography:** Bricolage Grotesque (headings), Hanken Grotesk (body), Noto Sans Kannada  
- **Mapping:** Leaflet + react-leaflet + OpenStreetMap (SSR disabled for zero server crashes)  
- **State & i18n:** React Context + `useSyncExternalStore` + `localStorage` persistence  
- **Sharing:** LZ-String URI compression (`/trip?d=...`) — zero database needed  
- **Testing:** Vitest (9 test suites, 37 automated unit & integration tests)  
- **Hosting:** Vercel Edge & Serverless  

> **Speaker Notes (2:55 - 3:35):**  
> *"Our architecture requires zero heavy external databases or complicated infrastructure. By using lz-string URL compression, entire multi-day itineraries can be shared in a single link. Leaflet and OpenStreetMap give us beautiful interactive maps without billing risks. And Vitest guarantees our 37 unit tests — covering candidate scoring, geo distances, cost invariants, and error resilience — pass on every single commit."*
